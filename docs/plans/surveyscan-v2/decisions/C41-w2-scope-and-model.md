# C41 — волна 2: процессы жизненного цикла и склад (объём, модель, инварианты, приёмка)

Статус: **проект на приёмку пользователя** (C41.01–C41.04). Код волны 2 (C42–C45) начинается после приёмки:
по C41.04 сценарии и акты согласуются до кода. Статусы в plan.json не меняются.
Основа: спецификация 0.5, раздел 25 «Волна 2»; решения пользователя 2026-11-15 (ниже).

## C41.01 — объём (решения пользователя 2026-11-15)

Входит (все четыре группы процессов):
1. **Учёт и движение:** постановка на учёт (приход), выдача сотруднику / на площадку, возврат на склад,
   перемещение между складами/ячейками.
2. **Ремонт и замена:** отправка в ремонт и возврат из ремонта; замена комплектующего (снято → поставлено) с
   историей на активе.
3. **Резерв и инвентаризация:** резервирование под получателя/основание; инвентаризация склада — сверка факта с
   учётом, акт расхождений, корректировка только через движение.
4. **Списание:** вывод из эксплуатации и списание с основанием (акт), без восстановления.

Решено:
- **Согласований нет** — операцию выполняет кладовщик/оператор; кто, что, кому, когда и по какому основанию —
  в журнале движений, истории актива и аудите. (Согласования можно добавить позже как отдельный шаг, модель это
  допускает: у операции есть состояние.)
- **Финансы не входят:** только количество. Цена, амортизация, бухгалтерия, лицензии (SAM) — **вне волны 2 явно**
  (D-01 остаётся в силе).
- **Документы:** акт выдачи, возврата, ремонта и списания, а также акт инвентаризации — **печатная форма в Web с
  сохранением в PDF** (печать браузера «Сохранить как PDF»). Серверная генерация PDF не делается: ей нужен
  встроенный шрифт с кириллицей (лицензия, размер выпуска). Если нужен PDF, который формирует сервер, — отдельное
  решение. Номер акта — сквозной по организации и году, в акте: номер, дата, тип операции, позиции с серийными
  номерами и количеством, откуда/куда, кто выдал, кто получил, основание.

Не входит: закупки и поставщики, заявки пользователей (это W3, C48), интеграция с 1С (возможна через webhook/API
позже), штрихкоды как отдельная функция (серийный/инвентарный номер вводится вручную или сканером как текст).

## C41.02 — сущности склада

| Сущность | Смысл | Ключевые поля |
|---|---|---|
| `warehouse.locations` | Склад или ячейка (дерево: склад → ячейка), привязаны к площадке C04 | location_id, site_id, parent_id, kind (warehouse/bin/repair/external), name |
| `warehouse.items` | Позиция каталога: модель/номенклатура | item_id, name, kind (**serial** / **quantity**), unit (шт, м, …), category, совместимость |
| `warehouse.units` | **Серийный экземпляр**: один физический предмет | unit_id, item_id, serial, inventory_no, **asset_uid** (если это актив реестра), state, location/holder |
| `warehouse.lots` | **Количественная партия** (кабели, расходники): остаток по месту | item_id, location_id, quantity ≥ 0 |
| `warehouse.reservations` | Резерв экземпляра или количества под получателя/основание | target (unit или item+qty+location), holder, basis, expires_at, state |
| `warehouse.movements` | **Журнал движений** (только дописывается): одна операция = одна запись документа и строки | movement_id, kind, from, to, holder, basis, actor, at, act_no; строки: unit_id или item+qty |
| `warehouse.component_events` | Установка/снятие комплектующего на актив | asset_uid, unit_id, kind (installed/removed), movement_id |

Правила модели:
- Серийный экземпляр, ставший активом реестра, связан с `asset_uid`; **движение не меняет asset_uid** (C25).
  Сопоставление «экземпляр ↔ актив» — по серийному номеру из инвентаризации (как C26-компоненты) или вручную.
- **ID партии не выдаётся за asset_uid**: количественные предметы активами реестра не становятся.
- Держатель (holder) — человек или команда из C27 (`responsibility.subjects`) либо место (склад/ячейка/ремонт).
- Состояния экземпляра: `in_stock` → `reserved` → `issued` (у держателя) → `in_repair` → `in_stock` …;
  `written_off` — конечное. Жизненный цикл актива реестра (`lifecycle_state`, вывод из учёта C42-частично)
  синхронизируется: списание экземпляра-актива выводит актив из учёта с тем же основанием.

## C41.03 — транзакционные инварианты

1. **Нет двойной выдачи:** экземпляр в одном состоянии и у одного держателя; выдача — условное обновление
   `state='in_stock'|'reserved'(своим резервом)` в той же транзакции, что и запись движения; конкурентная вторая
   выдача получает конфликт (409), а не вторую запись.
2. **Нет отрицательного остатка:** списание количества — `UPDATE … SET quantity = quantity - n WHERE quantity >= n`;
   0 строк — отказ. CHECK `quantity >= 0` в БД.
3. **Остаток выводится из движений:** таблица остатков — проекция журнала; проверка «пересчитать из движений =
   текущий остаток» (восстановление остатков) входит в тесты и в команду диагностики.
4. **Журнал только дописывается:** исправление — обратным движением (сторно) с основанием, не правкой.
5. **Одна операция — одна транзакция:** движение, смена состояния/остатков, событие outbox (`warehouse.*.v1`,
   новые типы событий — вне C03, отдельный контракт W2), аудит и история актива; номер акта выдаётся в ней же.
6. **Резерв:** держит экземпляр/количество для своего держателя; чужая выдача зарезервированного — отказ;
   резерв истекает по сроку (фоновая работа), выдача по резерву его закрывает.
7. **Инвентаризация:** снимок учёта на начало, ввод факта, расхождения → корректирующие движения одной
   операцией по акту; во время инвентаризации ячейки движения по ней блокируются (или фиксируются как
   «после снимка» — решить при C45.01, по умолчанию блокировка).
8. Изоляция по организации (tenant) и правам площадок — как во всём реестре; новые права: `warehouse:read`,
   `warehouse:write` (кладовщик), `warehouse:admin` (каталог, склады, списание).
