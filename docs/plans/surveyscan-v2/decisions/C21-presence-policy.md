# C21.01 — политика присутствия (presence) узлов обнаружения

Статус: реализовано в коде (миграция 0058), **на приёмку пользователя**; статус пакета C21 в плане не меняется.

## Решение
- Источник присутствия в первой волне — обследования подсетей C51 (TCP/ARP/ICMP с collector площадки).
  Пульс агента, свежесть данных (C12/C14) и бизнес-состояние актива (вывод из учёта, C42) — **отдельные** сущности и
  presence не меняют.
- **Пропуск** засчитывается узлу только **полным** обследованием его подсети: результат без ошибок. Обследование с
  ошибками (часть проб не выполнена, таймаут) обновляет найденные узлы, но пропусков не засчитывает. Упавшее
  обследование (ничего не найдено и есть ошибки) — state `failed`, ничего не меняет.
- **missing** — после `DiscoveryMissAfter = 3` подряд засчитанных пропусков (`misses`), время перехода — `missing_since`.
  Одного потерянного ICMP/TCP-ответа или выключенного на время ПК мало.
- Найденный узел: `present`, `misses = 0`; если был `missing` — событие `returned` (счётчик `returns`).
- Каждый переход — событие `sources.discovery_host_events` (appeared / missing / returned, обследование, время):
  доказательство для Web («Изменения присутствия») и разбора.
- Позднее/повторное: повтор результата завершённого обследования идемпотентен (без новых пропусков и событий).

## Почему порог 3, а не время
Расписание обследований — не чаще раза в 60 мин; 3 прохода ≈ 3 часа при часовом расписании, сутки и больше — при
редком. Порог по числу полных проходов не зависит от расписания и не срабатывает, пока источник не работает
(нет проходов — нет пропусков), что и требует AC-31. Порог по времени отмечал бы пропавшими все узлы подсети при
остановке collector.

## Доказательства
- integration `TestC51…` (discovery_integration_test.go): один пропуск — не missing; обследование с ошибками
  пропуск не засчитывает; третий полный пропуск — missing с `missing_since`; возвращение — present, `misses = 0`;
  журнал событий проверяется по контракту `DiscoveryHostEventList` (c51-discovery); присутствие актива — по
  контракту `AssetPresence` (c21-presence): «в сети», затем «пропал» после 3 полных обследований без его адреса.

## Присутствие актива (C21.02, частично)
`GET /api/v1/assets/{asset_uid}/presence` (контракт c21-presence): узлы обследований, чьи адреса совпали с адресами
актива из его сетевых фактов (1.0 и 1.2). Актив «в сети», если найден хотя бы один его адрес; «пропал» — только если
пропали все; «нет обследований» — адресов актива нет в обследованных подсетях. В карточке — блок «Присутствие в
сети». Контракт карточки C09 не меняется.
