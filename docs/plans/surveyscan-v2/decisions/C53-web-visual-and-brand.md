# C53 — визуал Web, название продукта «ТАКТ», сверка с презентацией (решения пользователя 2026-11-18)

Основание: требование пользователя 2026-11-18 («визуал выглядит костыльно: названия не по сетке, карточки дешёвые,
два поиска в меню; поменять название продукта на название из презентации; логотип — в духе текущего»), презентация
«ТАКТ Каталог» (IT TASK, 12 слайдов). Статусы и счётчик в plan.json не меняются. C03 не меняется.

## Решения пользователя (2026-11-18)
- **Название:** сейчас — всё видимое пользователю **и имена бинарников/служб** (takt-*; служба TaktAgent), с
  совместимыми старыми именами на один релиз. Полная смена (Go-модуль, переменные SURVEYSCAN_*, пути, репозиторий) —
  **после завершения всех этапов**, вместе с переустановкой стенда. Домены подписей `SURVEYSCAN-*-V1` (C03) — не меняются.
- **Стиль:** как в презентации — тёмно-синий сайдбар, светлые панели, акцент маджента, вторичный синий.
- **Логотип:** знак «т» в контурном квадрате со скруглением + точка маджента (как нынешний «s»), подпись «такт / каталог».
- **После C53 в план:** отчёты ИБ/КИИ, интеграция SIEM (syslog/CEF), лицензии (SAM). БДУ ФСТЭК — не выбрано.

## Требования пользователя к реестру (2026-11-19)
Замечания к варианту 1: «очень много места съедает; прикинь, что их 1 млн; группировка; РСМ нету».
- **Плотность:** строка 30–36 px, без иконки в строке; сводка — одна полоса счётчиков (она же быстрые фильтры),
  а не карточки; компактные шапка и меню; колонки выбирает пользователь. Цель — 25–30 строк на 1080p.
- **1 млн активов:** поиск, фильтры, сортировка и счётчики — только на сервере (не «поиск на странице»); курсорная
  постраничность 100/250/500; сохранённые представления; массовые действия «все по фильтру»; выгрузка — фоновой задачей.
  Нагрузку проверить отдельно (паспорт C30 мерился на меньших объёмах).
- **Группировка:** слева дерево с счётчиками (площадка → сегмент → тип; ответственный → команда; сервис → компонент;
  ОС → версия), выбор узла сужает таблицу; группировка строк в таблице со сворачиванием.
- **РСМ (ресурсно-сервисная модель) — нет:** только сервисы C26 вручную со связями. Нужны дерево услуга → сервис →
  компоненты → инфраструктура, анализ влияния, схема РСМ — **отдельный этап после C53** (как отчёты ИБ/КИИ, SIEM, SAM).
Макет: [плотный реестр](C53-mockups/5-reestr-plotnyj.png). Код Web не менялся.
- **Главная единица — система, не хост** (пользователь 19.11: «кому нужны индивидуальные хосты, прежде всего нам
  нужно видеть системы; хост — финальный этап разворачивания»). Главный экран реестра — список систем (критичность,
  владелец, хостов, доля актуальных данных, проблемы), раскрытие: система → среда → компонент → хосты; связи
  «зависит от / от неё зависят». Отдельно — «хостов вне систем» как очередь разбора. **Фильтры на каждом уровне.**
  Это и есть основа РСМ: в модели данных нужны среды и компоненты систем (сейчас C26 — сервис и связи с активами).
  Макет: [системы](C53-mockups/6-sistemy.png). Карточки по цепочке раскрытия: [система](C53-mockups/7-karta-sistemy.png)
  (состав по средам, требует внимания, зависимости, ответственные, изменения), [компонент](C53-mockups/8-karta-komponenta.png)
  (хосты с фильтрами, отклонения от эталона: ОС, версии ПО, антивирус, порты, локальные админы),
  [хост](C53-mockups/9-karta-hosta.png) (почему устарело — причина и действие, 12 разделов, источники, история).
  [Схема сети](C53-mockups/10-shema-seti.png): уровни Площадки / L3 / L2 / Системы, узлы свёрнуты до подсетей с
  числом хостов (для 1 млн), подсветка системы, фильтры, панель узла и аномалий; значки типов устройств (шлюз/маршрутизатор, МЭ, коммутатор, сервер, гипервизор, ВМ, СХД, АРМ, принтер, точка доступа, неизвестное) на узлах, в составе свёрнутых узлов и в легенде — нужен тип устройства в модели актива. [Вход](C53-mockups/11-vhod.png).
  Новое в модели: эталон компонента (ожидаемые версии) и объяснение причины устаревания.

## Дерево здоровья (пользователь, 2026-11-19)
«Генеральный директор заходит и видит одну зелёную кнопку; плюсик — площадки; плюсик — состав систем со светофором
(зелёный/жёлтый/красный по мониторингу здоровья); раскрывая до деталей, доходит до атомарной метрики (CPU и т. п.),
которая красит в этот цвет». Макет: [здоровье](C53-mockups/12-zdorove.png) — компания → площадка → система → среда →
компонент → хост → метрика; у узла: цвет, «дочерние по цвету», «почему такой цвет»; панель метрики (график, порог,
правило), «как цвет поднимается вверх», действия (инцидент, заглушить).
**Этого в продукте нет — новый этап «Мониторинг здоровья»** (после или вместе с РСМ): сбор метрик агентом/SNMP
(CPU, память, диски, службы, доступность), правила порогов и длительности, правила подъёма статуса (хост → компонент
→ система → площадка → компания, учёт критичности), хранение рядов метрик, заглушение и связь с инцидентами ITSM.
Сейчас «здоровье» = только свежесть инвентаризации и присутствие (C21).

## 2. Визуал Web (C53.01) — что не так сейчас
- Нет единой сетки: заголовки, панели и таблицы в разделах выровнены по-разному; отступы задаются вручную.
- Карточки и панели — плоские рамки без иерархии, разные радиусы и тени.
- Два поиска в меню («Поиск» и «Поиск ПО») + поиск «на странице» в реестре.
- 13 пунктов меню одним списком с номерами 00–12, без групп.
- Цвета и шрифт не связаны с брендом презентации.

Предложение:
1. **Дизайн-токены**: сетка 8 px, ширина контента, радиусы, тени, типографика (одна шкала), цвета бренда из презентации —
   тёмно-синий `#0F1A2B` (сайдбар, тёмные блоки), маджента `#D6157A` (акцент, активное), синий `#1E7BB0` (вторичный),
   светлые панели `#F1F4F9`. Тёмная тема — по тем же токенам.
2. **Меню по группам** без номеров: *Реестр* (Активы, Сервисы/CMDB, Схема сети, Разбор конфликтов) · *Сбор* (Источники,
   Обследования сети, Portable) · *Работа* (Мои задачи, Обращения, Склад) · *Администрирование* (Оргструктура,
   Уведомления).
3. **Поиск**: убрать оба пункта из меню. Глобальный поиск — поле в верхней панели (Ctrl+K) с результатами по типам;
   «Поиск ПО» — вкладка/фильтр в разделе «Активы» («Где установлено ПО»).
4. **Единые компоненты**: заголовок страницы, панель, карточка-метрика, таблица, фильтры, пустое состояние, бейдж
   статуса — один вариант на весь продукт; карточка актива — шапка + вкладки разделов.
5. Проверка: снимки всех разделов (светлая/тёмная, 1440 и 1280 px) до/после, e2e как сейчас.

## 3. Название и логотип (C53.02)
- Продукт: **ТАКТ** (Технологии Активов, Коммуникаций и Телеметрии), компоненты как в презентации: **ТАКТ.Каталог**
  (центр и Web), **ТАКТ.Сенсор** (collector и агенты), portable — **ТАКТ.Сенсор Portable** (уточнить).
- Логотип в духе текущего (контурный квадрат со скруглением, строчная буква и точка-«пульс»): буква **«т»** и точка
  в цвете маджента; вариант с градиентом куба из презентации — для экрана входа.
- Где меняется: Web (заголовок, вход, title, favicon), тексты CLI/служб/установщиков, документация для пользователя.
- Где **не** меняется без отдельного решения: домены подписей `SURVEYSCAN-*-V1` (C03 заморожен — смена ломает
  совместимость подписей), путь Go-модуля, имена схем БД, репозиторий. Имена бинарников и служб — вопрос к пользователю.
