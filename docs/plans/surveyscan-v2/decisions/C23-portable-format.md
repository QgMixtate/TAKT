# C23.01/C23.03 — формат portable-пакета и импорт (код: v2/internal/portable)

Статус: формат и импорт реализованы и проверены тестами; workflow сбора (C23.02) реализован (`surveyscan-portable`, internal/portableaudit) и проверен в песочнице; **импорт в центр (C23.03 по HTTPS/реестр) и parity online/file на реальном аудите (C23.04) НЕ выполнены**.

- **Контейнер.** ZIP (stdlib), плоская схема: `manifest.json`, `manifest.sig`, `obs/<observation_id>.json`. Любые другие имена, `..`, абсолютные пути, обратные слэши,
  каталоги, дубликаты, лишние файлы вне manifest — отказ целиком.
- **Подпись.** Ed25519 (stdlib) по `SURVEYSCAN-PORTABLE-MANIFEST-V1\n` + JCS-канонический manifest; `key_id` = SHA-256(pub)[:16] hex; доверяются только заранее заданные ключи.
  Manifest содержит SHA-256 и размер каждого наблюдения. Manifest обязан быть в канонической форме (подписанные байты = разобранные байты).
- **Шифрование** (решение пользователя 2026-11-15, включается в Web). HPKE RFC 9180 из стандартной библиотеки Go
  (`crypto/hpke`, без новых зависимостей): DHKEM(X25519, HKDF-SHA256) + HKDF-SHA256 + AES-256-GCM. Шифруется весь
  подписанный ZIP; конверт `SURVEYSCAN-PORTABLE-ENC-V1\n` | key_id получателя (16 байт SHA-256 открытого ключа) |
  enc‖ciphertext, info = заголовок (переадресация другому ключу ломает расшифровку). Подпись источника проверяется
  после расшифровки — шифрование её не заменяет. Ключ центра — один на организацию, закрытая часть в хранилище
  секретов центра (OpenBao KV / приватные файлы), создаётся кнопкой «Включить шифрование» (аудит
  `source.portable_encryption_enabled`); открытый ключ подставляется в `init --center-key` (или `center-key` для
  готового каталога; другой ключ для того же каталога не принимается). `verify` на ПК для зашифрованного пакета
  показывает только адресата: содержимое проверяет импорт. Чужой ключ — 422 `PACKAGE_ENCRYPTION_KEY_UNKNOWN`,
  порча — 422 `PACKAGE_REJECTED`; консольный `portable-import` зашифрованный пакет не принимает (ключ — у работающего
  центра). Смена ключа не поддерживается (иначе пакеты, зашифрованные прежним, стали бы нечитаемыми).
- **Импорт.** Лимиты: файлов, размер файла, общий размер, коэффициент сжатия (zip-бомба), размер пакета. Нарушение пакета целиком — ошибка без приёма. Отдельное наблюдение:
  digest mismatch / tenant-source mismatch / нарушение схемы 1.2 / тот же ID с другим digest → карантин; тот же ID и digest → дубликат (идемпотентно). Late-наблюдения (старый collected_at) принимаются.
- **Не сделано:** сбор portable (host/network/mixed, прогресс, отмена), загрузка по HTTPS с докачкой, staging/checkpoints, mapping на реестр, подпись/ключ portable-источника в enrollment,
  проверка эквивалентности реестра online vs file. Проверено только на синтетических наблюдениях из фикстур C15.

## C23.02 — разовый portable-сбор (`surveyscan-portable`)
- `init --state DIR --tenant --site --scope`: личность (source_id, generation, key_id) и ключ Ed25519 в каталоге 0700/0600; печатает public_key для доверия при импорте. Повторный init не перезаписывает.
- `collect --state DIR (--out FILE | --dry-run) [--no-host] [--ssh-target F]... [--winrm-target F]...`: этот хост (Linux/Windows) и удалённые цели по очереди,
  ход в stderr, итог по секциям в stdout. Наблюдения профиля 1.2: source_kind=portable, source_record = kind/имя цели, clock_quality=estimated (офлайн-устройство
  без гарантии времени), монотонная последовательность в state (сохраняется до экспорта, номера не переиспользуются). Каждое наблюдение проходит схему 1.2 до экспорта.
  Ошибка цели не прерывает остальные (код выхода 3 — частичный результат); Ctrl-C прерывает без файла; пакет пишется во временный файл и публикуется
  без перезаписи (hardlink, на FAT/exFAT — rename после проверки). Служба не устанавливается, центр/PG/Bao не нужны.
- `verify --package FILE --public-key B64`: та же проверка, что при импорте (подпись, лимиты, digest, схема, карантин).

## C23.03 — импорт в центр (файловый путь, консоль сервера)
- Записи пакета — подписанные наблюдения (SignedObservation, домен SURVEYSCAN-OBSERVATION-V1, JCS), подпись — ключом portable-источника;
  key_id = первые 16 байт SHA-256 открытого ключа в форме UUID (= key_id привязки ключа в центре). Импорт проверяет подпись манифеста И каждой записи.
- Регистрация: `surveyscan-server portable-register --tenant --site --scope --source --generation --public-key` (значения из `surveyscan-portable init`):
  активный источник вида portable + привязка ключа (namespace host, scope площадки), аудит source.portable_registered; повтор идемпотентен, иное поколение/ключ — конфликт.
- Импорт: `surveyscan-server portable-import --tenant --source --package FILE`: доверие — только активная привязка этого источника; пакет целиком отвергается
  при неверной подписи/ключе/лимитах; записи проходят общий конвейер IngestAuthorized (привязка ключа, дедуп, сопоставление с активом), авторизация — только
  этот portable-источник. Повторная загрузка идемпотентна (duplicate), обрыв продолжается повтором. Отчёт — JSON по записям.
- Не сделано: HTTPS-загрузка (API/веб), отдельный staging/checkpoints-журнал для пакетов (идемпотентность даёт конвейер), отзыв/ротация ключа portable-источника,
  проекция фактов при импорте из консоли (выполняет работающий сервер — не проверено), parity online/file (C23.04).
