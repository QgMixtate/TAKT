# C23.04 — узлы обследования и «доступа нет» в portable-пакете (принят пользователем 2026-11-18)

Основание: C52.06 п. 1–4 (требования пользователя 2026-11-17), решение «Портировать всё» и «предложи проект»
(2026-11-18). Статусы и счётчик в plan.json не меняются. C03 не меняется; C23 расширяется только добавлением —
пакеты прежнего формата импортируются как раньше.

## Что добавляется в пакет
Новый необязательный файл **`discovery.json`** рядом с `manifest.json`. Он перечислен в манифесте (поле
`discovery`: sha256 и размер), поэтому покрыт той же подписью манифеста; без записи в манифесте файл — отказ импорта.
`format_version` остаётся 1: старый центр отвергнет пакет с лишним файлом (как сейчас), новый — примет оба вида.

```json
{
  "schema_version": {"major": 1, "minor": 0},
  "ranges": ["10.20.0.0/16"],          // что обследовалось (после исключений)
  "excluded": ["10.20.5.0/24"],
  "started_at": "…", "finished_at": "…",
  "complete": true,                     // false — обследование прервано (Ctrl+C, лимит времени)
  "hosts": [
    {"ip": "10.20.1.15", "ports": [22], "kind": "linux_ssh",
     "outcome": "collected", "observation_id": "…"},
    {"ip": "10.20.1.40", "ports": [5985, 5986], "kind": "windows_winrm",
     "outcome": "no_access", "reason": "AUTH_FAILED", "profile": "domain-admins-ro"},
    {"ip": "10.20.1.77", "ports": [], "kind": "unknown", "outcome": "no_profile"}
  ]
}
```
- `kind`: `linux_ssh` | `windows_winrm` | `network_snmp` | `unknown` (по открытым портам и баннеру, как D13).
- `outcome`: `collected` (есть наблюдение в этом же пакете — ссылка `observation_id`), `no_profile` (ни одно
  правило привязки не подошло), `no_access` (профиль подошёл, вход/права отклонены), `unreachable` (ответил при
  обследовании, но сбор не дошёл: сеть, таймаут), `skipped` (снято аудитором в мастере).
- `reason` — фиксированные коды как у целей Web: `AUTH_FAILED`, `ACCESS_DENIED`, `TLS_FAILED`, `HOST_KEY_UNKNOWN`,
  `TIMEOUT`, `HOST_UNREACHABLE`, `KERBEROS_*`. Никаких текстов ошибок, логинов, паролей, ключей.
- `profile` — **имя** профиля учётки из файла профилей (без логина/секрета); правила привязки — в пакет не идут.
- Лимиты: до 65 536 узлов, файл до 16 МиБ; IP только из `ranges`; повтор IP — отказ.

## Что делает центр при импорте
- Наблюдения — как сейчас (C23.03): активы, сопоставление, разбор конфликтов.
- Узлы из `discovery.json` пишутся в новую таблицу модуля sources **`portable_discovery_hosts`**
  (tenant, portable source, ip, kind, ports, outcome, reason, profile, package, seen_at); повтор пакета — без
  изменений (идемпотентно по package_id + ip). **Актив-пустышка не создаётся.**
- Web, «Portable-аудит» → карточка источника → **«Найденные узлы»**: таблица с фильтром по исходу; `collected` —
  ссылка на актив; `no_access/no_profile` — подсказка «добавьте профиль/правило и повторите аудит» или «создать
  цель сбора» (если узел в подсети центра и до него есть сеть — переход в «Обследования сети», без автосоздания).
- Отчёт импорта: «узлов найдено N, собрано M, без доступа K, без профиля L».
- Аудит: `source.portable_imported` с числами (без IP в тексте события).

## Чего нет
- Присутствие (present/missing C21) по portable не ведётся: офлайн-снимок — не регулярное наблюдение.
- Пароли/ключи профилей и правила привязки в пакет и в центр не попадают.
