## 2. KVM на .5 (mvp)
1. Если на .5 нельзя (мало ресурсов/запрет) — спросить пользователя, на какой Linux-узел. Вложенная виртуализация
   не нужна: проверяем по **выключенным** ВМ (libvirt показывает их в `list --all`).
2. Установка (с «да» — дано): `apt-get install -y --no-install-recommends libvirt-daemon-system libvirt-clients qemu-system-x86`
   (или аналог для ОС узла). Сеть `default` libvirt — оставить выключенной (`virsh net-autostart default --disable`;
   если запущена пакетом — `virsh net-destroy default`), чтобы не было моста 192.168.122.0/24 и NAT на узле.
3. Учётке SSH-цели .5 (под ней собирает collector) — **только чтение libvirt**: `usermod -aG libvirt <учётка>`;
   проверить под ней: `virsh --readonly -c qemu:///system list --all`.
4. Определить (не запускать) две тестовые ВМ: `t31-web` (2 vCPU, 1 ГБ, диск-файл 1 ГБ в пуле `default`, интерфейс в
   сети `default`) и `t31-db` (1 vCPU, 512 МБ, без диска): `virt-install --print-xml` или XML вручную → `virsh define`.
   Пул `default` — `/var/lib/libvirt/images`. ВМ **не запускать**.
5. В отчёт — команды и вывод `virsh --readonly list --all`, `net-list --all`, `pool-list --all`.

## 3. Проверка C57
1. В течение ~1 мин после старта collector (затем раз в период цели, не чаще 15 мин) — в журнале collector
   `target_<id>_kvm_snapshot_sent`; при `kvm_unavailable` / `kvm_snapshot_rejected` — причина.
2. Web → «Сбор» → «Платформы»: платформа KVM «<имя .5>», объекты: хост, 2 ВМ (выключены), сеть `default`, пул
   `default`; «не обследованы» — 2 ВМ (агента внутри нет — так и должно быть). Скриншоты.
3. Объект «хост» KVM: ссылка «карточка хоста» **или** «не обследован» — записать, что видно (сопоставление по UUID
   требует BIOS UUID в SSH-сборе .5 — фиксируем факт).
4. Удаление: `virsh undefine t31-db` (тестовая ВМ, «да» дано). Через 3 сбора KVM (≈45 мин; можно «Собрать сейчас»
   на цели .5 трижды с интервалом) — `t31-db` «удалён из платформы». Скриншот.
5. Компьютеры AD: после **полной** синхронизации каталога (раз в сутки; «Синхронизировать сейчас» с полной
   синхронизацией, если есть в Web) — платформа «Active Directory»: компьютеры домена, у win-ar и DC — «карточка
   хоста» (сопоставление по имени). Скриншот. DC — только чтение.
6. Раздел «Платформы» — пустых/сломанных экранов нет; фильтр «не обследованы» и фильтр по виду работают.
7. Hyper-V: на WinRM-целях (win-ar, DC) роли Hyper-V нет — в журнале collector нет `hyperv_snapshot_*`, платформа
   Hyper-V в Web не появляется, на узлах ничего не меняется. Записать, что видно (строки журнала про Hyper-V — какие есть).

8. **Обратный DNS (C57.03, только при 78+ миграциях):** «Обследования» → подсеть 10.170.108.0/24 → «Запустить обследование» (или дождаться
   плановое): в списке узлов под IP — имена из DNS (DC, win-ar, mvp…, если в DNS стенда есть PTR-записи). У каких узлов
   имени нет — записать (возможно, нет PTR-зоны). Скриншот. В форме «Собирать…» у узла с именем поле имени сервера
   заполнено им.

## 5. Разведка ESXi и zVirt (для C57.03; ничего не менять)
Спросить пользователя и записать (без паролей):
1. ESXi: адрес (в 10.170.108.0/24?), версия, есть ли vCenter (или только отдельный ESXi), сколько ВМ.
2. zVirt: адрес engine, версия zVirt, сколько хостов/ВМ.
3. С ВМ центра/collector — доступность API **без входа**: `curl -sk -o /dev/null -w '%{http_code}\n' https://<esxi>/sdk`
   и `https://<engine>/ovirt-engine/api` (ожидаем 401/200/302 — записать код; TLS-сертификат — самоподписанный или
   корпоративный, `openssl s_client -connect <адрес>:443 </dev/null | openssl x509 -noout -subject -issuer`).
4. Может ли пользователь завести **учётку только на чтение** (ESXi: роль «Read-only»; zVirt: роль `ReadOnlyAdmin`
   или аналог) — только ответ «да/нет/когда»; заводить — в задании C57.03, пароль вводит пользователь сам.
