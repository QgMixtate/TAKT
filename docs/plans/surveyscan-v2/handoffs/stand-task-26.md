# Задание №26 для локального Claude (стенд awm.local): OpenBao без root-токена на ВМ (ISSUES №111) и выкладка

**Этап:** закрытие C53/C54. **«Да» пользователя (26.11):** №111 — unseal-ключ хранить у пользователя вне ВМ, root-токен
отозвать, `bao-init.json` с ВМ удалить.
**Почему по шагам:** `scripts/vm_center.py` при каждом запуске центра (в т. ч. ночной копией) выпускал токен центра
root-токеном из `v2/.local/bao-init.json`. Теперь есть узкий **токен выдачи** (`--setup-issuer`): умеет только выпустить
токен центра по роли и продлить себя (30 дней, продлевается при каждом запуске центра). Без него отзыв root сломал бы
запуск центра.

**Правила — как всегда.** Ключ, root-токен, токены в чат, отчёт, журнал и файлы не попадают (только «есть/нет»,
хеши SHA-256). Ничего не удалять до проверки шага, который на это указывает.

## 1. Выкладка
Последний `develop` с зелёным CI (не раньше коммита с этим заданием): центр, collector, Web; миграций 76.
Скриншоты для приёмки C53/C54: «Источники» — строка WinRM DC «не собрано: Сеть — нет прав у учётки», таблица с
открытой панелью прокручивается (№109/110); карточка «Серверы Linux» — число хостов в шапке = в таблице (№113).

## 2. Где ещё лежит ключ
`find / -xdev -name 'bao-init.json*' 2>/dev/null` и поиск в наборах копий (`/var/backups/surveyscan`: в каталогах и
архивах `state/*`). В отчёт — список путей (без содержимого). **Если файл есть в наборах копий — ничего не удалять,
сообщить**: решение пользователя (после отзыва root в копиях останется только unseal-ключ).

## 3. Токен выдачи
Из `v2` тем же пользователем, что запускает центр: `.contract-tools/bin/python scripts/vm_center.py --setup-issuer`
(тот же `--state`, что у центра, если он не по умолчанию). Ожидается: «токен выдачи … создан» и «токен центра выпущен
токеном выдачи». Файл `.local/vm-center-state/bao-center-issuer.token` — 0600. Перезапустить центр обычным способом:
`/health/ready` 200, в журнале нет «OpenBao: токен центра не действует».

## 4. Unseal-ключ — к пользователю
Пользователь сам, в своём терминале (не через тебя), сохраняет ключ (`keys_base64[0]` из `bao-init.json`) в свой менеджер
паролей / офлайн. Проверка без показа: ты считаешь SHA-256 ключа из файла, пользователь — SHA-256 сохранённой копии;
в отчёт — «совпало» (сами хеши не нужны). Без «совпало» дальше не идти.

## 5. Отзыв root-токена и удаление файла
1. root-токеном из файла — `POST /v1/auth/token/revoke-self` (значение не выводить). Проверка: `GET /v1/auth/token/lookup-self`
   этим значением — 403.
2. `shred -u v2/.local/bao-init.json` (и копии, найденные в шаге 2 вне наборов копий — список в отчёт до удаления).
3. Проверка: перезапуск центра — ready 200 (токен выдан токеном выдачи); ручной запуск копии (`surveyscan-stand-backup`)
   — код 0, verify ок.

## 6. Как теперь (записать пользователю в отчёт)
- После перезагрузки ВМ OpenBao запечатан: `python3 scripts/dev.py unseal` — ключ вводит пользователь (не сохраняется).
- Новый root-токен (учения восстановления и т. п.) — только по ключу: `bao operator generate-root` (C39).
- Токен выдачи живёт 30 дней без запусков центра; ночная копия перезапускает центр и продлевает его.
