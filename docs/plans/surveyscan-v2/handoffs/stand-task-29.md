# Задание №29 для локального Claude (стенд awm.local): мастер portable по макетам, брандмауэр центра, вывод источников

**Этап:** C52.04, последняя проверка перед приёмкой. **Решения пользователя (27.11, «1а 2а 3а»):** №126 — правило
брандмауэра на порт центра только для 10.170.108.0/24; замолчавшие источники пользователь выводит сам кнопкой; мастер
portable — по утверждённым макетам версии 2.

**Правила — как в №28.** Ничего вне 10.170.108.0/24; DC — только чтение. Пароли учёток вводит пользователь сам в мастере
(в памяти мастера, на диск не пишутся) — не в чат, отчёт и файлы. Действия вне задания — только с «да» пользователя.

## 1. Выкладка
Последний `develop` с зелёным CI (не раньше коммита с этим заданием). Выпуск **0.0.0-c29** как в №28 (`make build rust
packages VERSION=0.0.0-c29`, Web, `release.py build/sign/stage` тем же ключом), перезапуск центра с `--release-dir …/stage-c29/…`
(адрес для сети стенда и ключ запомнены). Журнал: «файлы установки: выпуск 0.0.0-c29 … true».

## 2. Брандмауэр центра (№126)
Порт центра для установщиков (строка журнала «центр для установщиков …:<порт>»):
`sudo iptables -I INPUT -p tcp --dport <порт> ! -s 10.170.108.0/24 -j DROP` — перед этим показать пользователю правило и
получить «да». Проверка: с Astra (10.170.108.11) `curl --cacert … https://10.170.108.2:<порт>/api/v1/registration/ca` — 200;
`iptables -L INPUT -n --line-numbers` — правило есть. Правило не переживает перезагрузку ВМ — записать в отчёт, нужно ли
сохранять (`iptables-persistent`) — решение пользователя.

## 3. Вывод замолчавших источников (№131)
Пользователь сам: «Источники» → строка агента №19 (`125c7683…`) → «Вывести из работы», причина «заменён новой установкой»;
collector Astra (`a73c8a4d…`) — «выведен из эксплуатации». Проверить: состояние «отозван», счётчик «агентов молчат > 24 ч»
уменьшился; карточки win-ar и Astra — те же активы.

## 4. Мастер portable на ПК пользователя (главное)
1. Web «Portable-аудит»: площадка и сегмент стенда → **«Копировать строку»**. Скачать из «Источники → Установка → Скачать»
   `surveyscan-portable_0.0.0-c29_windows_x64.exe` на носитель (флешка или каталог-носитель).
2. Запуск: `surveyscan-portable.exe wizard --state .\ss-portable` — открылся браузер с мастером. Скриншоты каждого шага.
3. **Шаг 1:** вставить строку → видны площадка, сегмент, «ключ шифрования центра получен» → «Подготовить носитель» →
   блок для центра — в Web «Зарегистрировать носитель».
4. **Шаг 2:** подсеть `10.170.108.0/24` (DC 10.170.108.1 — исключить, если пользователь скажет) → «Начать обследование».
5. **Шаг 3:** профили — пользователь заводит и вводит пароли сам: SSH для Linux (учётка аудита стенда), WinRM для win-ar
   (доменная или «текущая учётка Windows», если ПК в домене). Правила: Linux → SSH-профиль, Windows → WinRM-профиль.
   «Проверить вход» на одном узле — результат в карточке (вход выполнен / причина).
6. **Шаг 4:** «Собрать выбранные». Ожидается: часть узлов «собрано», `simple2fa` (второй фактор SSH) — «вход отклонён /
   второй фактор» — **открыть его страницу узла**: цепочка остановлена на «вход», «почему» и «как исправить» понятны.
   «Только проблемы» — узлы сгруппированы по причине. Если есть «частично» — открыть страницу, записать причину.
7. **Шаг 5:** итоги по разделам и файл пакета с SHA-256 → загрузить пакет в Web: «принято: N», без новых дублей хостов
   (win-ar, Linux-ВМ — те же активы; узлы без доступа — в «Найденных узлах»).
8. Оценка пользователя: удобно ли, что непонятно — в отчёт дословно.

## Отчёт
Разделы 1–4: sha, строка журнала, правило iptables и curl, состояния источников, скриншоты шагов мастера и страницы
узла simple2fa, итог импорта, хосты до/после, отзыв пользователя о мастере. Новые замечания — с №132.
