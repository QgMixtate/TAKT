## A. Portable на ПК аудитора (можно до конца прогона, с «да»; центр не меняется)
1. Windows-ПК аудитора в домене (win-ar или другой, по решению пользователя), под доменной учёткой с правом WinRM:
   `surveyscan-portable.exe wizard --state D:\audit` (или на Linux: `./surveyscan-portable wizard --state ~/audit`) —
   откроется браузер на `http://127.0.0.1:<порт>/#…`. Проверить: адрес работает только с этого ПК; с другого ПК —
   нет (привязка к 127.0.0.1).
2. **Подготовка:** tenant/site/scope — из Web «Portable-аудит» (новый источник «стенд №19»); ключ шифрования центра —
   оттуда же. Открытый ключ — в центр (доверие).
3. **Обследование:** `10.170.108.0/24`, исключить адрес DC (по решению пользователя), скорость по умолчанию (200/с).
   В отчёт: найдено узлов по видам; .5/.7 — Linux/SSH, .10 и win-ar — Windows; ложных узлов нет.
4. **Профили** (пароли не сохраняются): `linux-ro` (SSH, пароль, тестовая учётка), `win-me` (WinRM, «текущая учётка
   Windows»), при желании `win-pw` (WinRM, пароль, KDC = DC — Kerberos). Правила: Linux/SSH → `linux-ro`,
   Windows → `win-me`. «Проверить вход и сбор» на одном Linux и на win-ar.
5. Сбор отметить .5, .7, win-ar (+ «этот ПК»), **сухой** не нужен — мастер сохранит пакет в `D:\audit\packages\`.
   Ожидание: Linux — `collected`, win-ar — `collected` (Kerberos/NTLM текущей учётки), узлы без профиля —
   «нет профиля», снятые — «пропущен». Неверный пароль (одна попытка) — `AUTH_FAILED`, без блокировки учётки.
6. Если на win-ar вход текущей учёткой даёт `ACCESS_DENIED` — проверить, что учётка в группе из
   `prepare-winrm-target.ps1`/GPO №17; в отчёт — код, без текста ошибки. Если `SCRIPT_FAILED` — повторить из
   консоли с `set SURVEYSCAN_AGENT_DEBUG=1` и `surveyscan-portable.exe collect --state D:\audit --dry-run --no-host
   --only <ip>`; в отчёт — строка `winrm debug:` (без инвентаря).
7. Пакет пока **не загружать** (центр ещё без 0069) — загрузка в части B.

## C. Rust-агент (с «да»; после B)
1. **Linux** (.7 или другой тестовый, не DC): остановить Go-агент, если стоит; код регистрации из Web;
   `sudo SURVEYSCAN_REGISTRATION_CODE=<код> ./surveyscan-agent register --collector https://<collector>:8443
   --fingerprint <отпечаток> --config /etc/surveyscan-agent/agent.json --state /var/lib/surveyscan-agent`, затем
   `surveyscan-agent run --config …` под systemd (юнит Go-агента с заменой бинарника). Ожидание: heartbeat, сбор 1.2,
   тот же актив, источник «Агент хоста»; размер бинарника и память (RSS) — в отчёт против Go-агента.
2. **Windows** (win-ar, с «да»): `surveyscan-agent.exe register …` (как выше, пути ProgramData), затем
   `surveyscan-agent.exe install-service --config C:\ProgramData\SurveyScan\agent.json` → служба `SurveyscanAgent`
   (автозапуск отложенный, LocalSystem). Ожидание: 12 разделов 1.2, тот же актив W; перезагрузка ПК — служба
   поднялась сама; `uninstall-service` после теста — по решению пользователя.
3. Обрыв: выключить collector на 10 мин — агент копит очередь, после включения доставляет без дублей.
