# Задание №14 для локального Claude (стенд awm.local): присутствие узлов, шифрование portable, склад (пилот W2)

**Запускать после отчёта по заданию №13 и после того, как облачная сессия назовёт коммит выкладки с зелёным hosted
CI.** Текст читать с `origin/develop`. Миграций после выкладки — **62** (0058 присутствие, 0059–0061 склад).

Правила (как всегда): sudo — только по подтверждению пользователя, временный sudoers удалить в конце; пароли и ключи
вводит **пользователь сам в Web**; DC — только чтение; изменения на win-ar — с подтверждения пользователя; ничего не
сканировать вне 10.170.108.0/24; секреты, ключи, сырой инвентарь в отчёт не попадают.

## 1. Копия и выкладка
Как в №13: свежая копия (`surveyscan-stand-backup.service` + `checkpoint.py verify` — OK, без неё не продолжать),
`git checkout <коммит>`, `make build`, центр через vm_center `--persistent --backup-marker …` (**62** миграции), новые
агент/collector в `/opt/surveyscan`, перезапуск служб (sudo), Web из коммита (`npm ci && npm run generate && npm run
build` → `~/ss-web`, `version.json` — коммит). Ctrl+F5. В меню появился пункт **«Склад»**.

## 2. Присутствие узлов (C21)
1. «Обследования сети» → подсеть стенда → «Обследовать» дважды подряд (между ними выключить один тестовый узел,
   который не жалко, — **только с подтверждения пользователя**; DC и win-ar не выключать). Ожидание: у выключенного
   узла «не найден 1 из 3», затем «2 из 3» — **не** «пропал».
2. Третье полное обследование → «пропал» с датой; внизу «Изменения присутствия» — запись «пропал». Включить узел,
   обследовать → «вернулся».
3. Карточка актива этого узла → блок «Присутствие в сети»: «в сети» / «пропал из сети» по шагам выше.
4. **Площадка недоступна (C21.04):** остановить collector (sudo, с подтверждения) → «Обследовать» → обследование не
   выполнится (или «ошибка»); ни один узел не должен получить пропуск. Запустить collector обратно.
В отчёт: снимки «не найден N из 3», журнал переходов, что было при остановленном collector.

## 3. Шифрование portable (C23)
1. «Источники данных» → «Portable-аудит» → «Включить шифрование» → команда `init` содержит `--center-key`.
2. На ВМ стенда (Linux): `init` по команде из Web в новом каталоге → вывод в Web → «Зарегистрировать» → `collect`
   → вывод `EXPORTED … encrypted for the centre`; `verify` → `ENCRYPTED: package for centre key …`.
3. Загрузить пакет в Web → «принято», «пакет был зашифрован». Проверить, что `strings audit.zip | grep -i <имя хоста>`
   ничего не находит (содержимое не читается без ключа центра).
4. Если центр работает без OpenBao — убедиться, что каталог `integrations` рядом с конфигурацией центра попадает в
   копию (BACKUP.md): в отчёт — да/нет.
5. Необязательно (с подтверждения): то же на win-ar (раздел 6а задания №13, но с `--center-key`).

## 4. Склад — пилот волны 2 (C45.04)
Пользователь в Web (раздел «Склад», OPERATIONS.md раздел 13):
1. Справочники: склад «ИТ-склад» на площадке стенда, ячейка «Полка 1», место «Сервис-центр»; позиции «Ноутбук»
   (по серийным), «Модуль памяти» (по серийным, подходит к модели одного из ПК стенда — модель взять из карточки),
   «Патч-корд» (количеством, шт).
2. Приход: 2 ноутбука (вымышленные серийные), 2 модуля памяти, 20 патч-кордов → акт приёма, «Печать / PDF» —
   сохранить PDF (в отчёт: открылся ли, кириллица читается).
3. Выдача ноутбука сотруднику из оргструктуры → акт выдачи; возврат → акт возврата; «Сторно» ошибочной выдачи.
4. Резерв второго ноутбука за сотрудником; попытка выдать его другому — отказ; выдача тому же — проходит.
5. Установка модуля памяти на актив стенда: подходящий — проходит; неподходящий — предупреждение и только с
   «под мою ответственность». В карточке актива — блок «Склад» с операциями.
6. Инвентаризация «Полки 1»: начать → ввести часть серийных и посчитанное количество патч-кордов (на 2 меньше) →
   сверка → «Закрыть и провести» → акты недостачи/излишка; на время инвентаризации приход на полку — отказ.
7. `surveyscanctl warehouse units --holder <сотрудник> --output table` и `warehouse verify` (пустой список).
8. «Экземпляры» → фильтр «За кем числится» → CSV, открыть в Excel/LibreOffice (кириллица).
В отчёт: удобство форм, непонятные надписи, ошибки; номера актов; скриншоты без персональных данных.

1. **Portable на Windows** (раздел 6а №13) — на **новом ПК** без агента и цели сбора, с подтверждения пользователя:

   включено) → регистрация → `collect` → `verify` → загрузка → дубли/аудит (`source.portable_registered`,
   `source.portable_imported`) → повторная загрузка (без изменений) → удалить каталог portable на ПК.
2. Исправления по отчёту №13: на вкладке «Учётки сбора» у учётки виден статус, «Отключить»/«Включить» спрашивают

   выбор причины из списка + уточнение. `prepare-winrm-target.ps1` из коммита выкладки на win-ar **не запускать
   повторно без нужды** (исправление проверено в CI на Windows Server 2022); если запускали — вывод в отчёт.
3. Не делать без решения пользователя: перевод DC на Web-цель и отключение `surveyscan-winrm2`; удаление дубля
