# Задание №17 для локального Claude (стенд awm.local): WinRM через групповую политику и «CA домена»

**Когда:** после №15–16 (можно в той же сессии), на той же выкладке. Руководство — `v2/deploy/OPERATIONS.md`,
раздел 11 (дословно по нему: задача — проверить, что по документу можно сделать, и отметить, где пришлось догадываться).

Правила: **все изменения в домене (OU, группы, GPO, AD CS) делает пользователь сам** или с его явного «да» на каждый
шаг — DC в остальном только для чтения; на win-ar — перезагрузка и `gpupdate` только с подтверждения; пароли вводит
пользователь; секреты, отпечатки ключей учёток и персональные данные в отчёт не попадают.

## 1. Подготовка (пользователь в «Пользователи и компьютеры AD» / «Управление групповой политикой»)
1. Тестовое подразделение `OU=SurveyScan-Test` и в нём **только win-ar** (перенос компьютера — действие в домене,
   с «да» пользователя). Записать исходное OU win-ar — в конце вернуть.
2. Группа `AWM\SurveyScan-Collect`, в ней учётка сбора `AWM\scanwinrm` (если группы ещё нет).
3. Скрипт `prepare-winrm-target.ps1` из коммита выкладки — в `\\awm.local\NETLOGON\surveyscan\` (чтение для
   «Компьютеров домена»).
В отчёт: что было уже готово, что создано.

## 2. GPO «SurveyScan WinRM» (раздел 11, пп. 1–5)
Пользователь создаёт GPO и привязывает к `OU=SurveyScan-Test`, строго по OPERATIONS.md раздел 11, пп. 1–5
(встроенные группы через «Настройку», служба WinRM, параметры WinRM с фильтром IPv4 = адрес collector, Basic и
незашифрованный — отключено, Kerberos — не запрещён, правила брандмауэра 5985/5986 только с адреса collector,
немедленная задача со скриптом `-Gpo -Kerberos`).
В отчёт: какие пункты документа непонятны или не совпали с интерфейсом (названия в русской Windows Server 2019).

## 3. Применение на win-ar
1. С подтверждения: `gpupdate /force`, перезагрузка win-ar.
2. На win-ar: `gpresult /r /scope computer` — GPO применена; `winrm enumerate winrm/config/listener` — 5985
   (и 5986, если будет сертификат); `net localgroup` для двух встроенных групп — есть `SurveyScan-Collect`;
   журнал задач — немедленная задача выполнилась (код 0).
3. Важно: win-ar уже был настроен скриптом вручную (№12–13). Проверка здесь — что политика применяется и сбор
   продолжает работать; **«чистый» ПК** (без ручной настройки) — когда появится новый ПК в домене: тогда весь
   раздел повторить на нём (в отчёт — отметить, что не проверено).

## 4. Сбор по Kerberos (HTTP 5985)
«Обследования сети» → цель win-ar (WinRM, HTTP 5985, Kerberos, учётка `AWM\scanwinrm`) → «Собрать сейчас» →
«собрано», данные в прежний актив (без дубля). На win-ar — событие 4624 для учётки сбора (тип входа 3, Kerberos).

## 5. «CA домена» и HTTPS 5986 (раздел 11, п. 6) — если в домене есть AD CS
1. Пользователь проверяет, есть ли служба сертификации (`certutil -config - -ping` или оснастка «Центр
   сертификации»). **Нет AD CS — раздел пропустить**, в отчёт «AD CS отсутствует». Разворачивать AD CS ради
   проверки — только по отдельному решению пользователя.
2. Есть AD CS: в GPO — автоматическая регистрация (п. 6), шаблон «Компьютер» с правом автоподачи для «Компьютеров
   домена». На win-ar (с подтверждения) `gpupdate /force` → `certutil -store My` — сертификат компьютера;
   немедленная задача скрипта создаёт прослушиватель 5986.
3. В Web: «Обследования сети» → «Учётки сбора» → загрузить корневой сертификат AD CS (открытый, `.cer`) как
   «CA домена»; цель win-ar → HTTPS 5986, проверка «CA домена» → «Собрать сейчас» → «собрано», тот же актив.
4. Отрицательная проверка: цель с проверкой «CA домена» на узел с самоподписанным сертификатом (если есть) —
   отказ с понятным текстом.

## 6. Возврат
Вернуть win-ar в исходное OU (с «да» пользователя), GPO оставить отключённой или удалить — по решению пользователя.
Цель сбора win-ar оставить в рабочем режиме (Kerberos 5985 или HTTPS 5986 — что выбрал пользователь).
