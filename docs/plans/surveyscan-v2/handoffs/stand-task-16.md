# Задание №16 для локального Claude (стенд awm.local): склад в браузере, portable на Windows, хвосты стенда

**Выполнять на той же выкладке, что и №15** (можно в той же сессии, после №15). Миграций — **68**. Правила — как в
№15: sudo только по подтверждению, временный sudoers удалить; пароли и ключи вводит пользователь сам; DC — только
чтение; изменения на win-ar и ПК — с подтверждения; ничего вне 10.170.108.0/24; секреты и персональные данные в
отчёт не попадают.

## 1. Склад в браузере (дозакрыть W2 — в №14 проверено только через API)
Пользователь в Web, раздел «Склад» (OPERATIONS.md, раздел 13), на данных из №14:
1. **Акт в PDF:** «Журнал и акты» → любой акт выдачи → «Печать / PDF» → сохранить PDF. В отчёт: открылся ли файл,
   читается ли кириллица, есть ли номер акта, основание, позиции, места для подписей.
2. **CSV:** «Экземпляры» → фильтр «За кем числится» → выгрузка CSV → открыть в Excel/LibreOffice: кириллица и столбцы
   на месте.
3. **Блок «Склад» в карточке актива:** актив, на который в №14 ставили модуль памяти → карточка → блок «Склад» —
   операции установки/снятия с номерами актов.
4. **Формы:** приход, выдача, возврат, перемещение, резерв, инвентаризация — пройти каждую форму руками (можно на
   вымышленных серийных), отметить неудобства и непонятные надписи. Неподходящее комплектующее — предупреждение и
   только с «под мою ответственность».
5. **Роли:** пользователь с ролью «просмотр» (если такой есть) видит склад, но кнопок операций нет; оператор не может
   списать (только администратор).
В отчёт: снимки форм (без ФИО), номера актов, всё, что было непонятно.

## 2. Portable на Windows (перенесено из №13/№14)
С подтверждения пользователя, на **новом ПК** без агента и цели сбора:
1. `surveyscan-portable.exe` из коммита выкладки (собрать `make build` → `.dist`, перенести на ПК).
2. «Источники данных → Portable-аудит» → команда `init` (с `--center-key`, шифрование включено в №14) → выполнить на
   ПК → вывод вставить в Web → «Зарегистрировать» → `collect` → `verify` (`ENCRYPTED: package for centre key …`).
3. Загрузить пакет в Web → «принято», «пакет был зашифрован»; новый актив без дублей; аудит
   `source.portable_registered`, `source.portable_imported`. Повторная загрузка — без изменений.
4. Удалить каталог portable на ПК.
В отчёт: шаги, ошибки, время сбора, размер пакета.

## 3. Хвосты стенда — **каждый пункт только по явному «да» пользователя**
1. **DC → цель сбора из Web.** «Обследования сети → Цели сбора»: цель DC (WinRM, учётка `AWM\scanwinrm` — пароль
   вводит пользователь), «Собрать сейчас» → данные в прежний актив DC (без дубля). Только после успешного сбора —
   отключить прежнюю службу `surveyscan-winrm2` (sudo, с подтверждения). На DC ничего не менять.
2. **Дубль Kerberos-цели `1d7cdb47`:** убедиться, что рабочая цель win-ar собирает, затем отключить (не удалять)
   дубль `1d7cdb47`; через сутки без ошибок — по решению пользователя удалить.
3. **Файлы учёток отключённых служб** (прежние файловые службы целей .5/.7/.10 и winrm2): удалять **не раньше
   2026-11-22** и только после того, как сборы по Web-целям идут без ошибок не менее суток. Перед удалением — список
   путей пользователю, удаление — по его «да» (sudo).
4. **win-ar (ISSUES №10):** в карточке win-ar проверить, собираются ли теперь ОС и CPU (раньше PermissionDenied по
   WinRM). Если нет — текст ошибки из карточки и `last_error` цели, ничего на win-ar не менять без подтверждения.

## 4. Отчёт
По разделам 1–3: прошло / не прошло, снимки без персональных данных, что удалено/отключено (только с «да»
пользователя), дубли/конфликты (0), временный sudoers удалён — да/нет, замечания по Web.

## Не входит (отложено пользователем)
Чистая ВМ с нуля по документации (C33.04, AC-01/19); сетевые устройства LLDP/FDB/VLAN/VRF (AC-30/35/36, нужен
реальный коммутатор); приёмочный прогон E2 по эталонам (C24); «CA домена» и GPO для WinRM; нагрузка 100
пользователей и 24 часа.
